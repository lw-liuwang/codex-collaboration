# 每个时段独立随机，当天计划锁定

2026-11-17用户要求每账号约5分钟随机唤醒、一次处理2–4条PR，并保留锁定的计划。协议1.4.0每天提供168个计划时刻，白天09–23；A/B计划错开2分钟。替代1.3.0的10分钟时段，现有两项原生任务直接更新，不新增任务。

## 随机与锁定

把白天分成168个5分钟时段，每个时段独立抽取一个小幅偏移：A从该段起点后1–2分钟开始，B在A之后2分钟。A相邻计划时刻相隔4–6分钟，平均约5分钟；不再每小时重复同一组分钟。原生客户端可能延迟实际派发，不能把名义预约当作已经执行，也不能保证两机实际启动始终错开2分钟。

Plan首次生成后保存`.local/plans/<actor>-<date>.json`，同一天、同版本后续调用直接读取，不改文件、不重抽。随机偏移来自日期、协议版本和时段序号的SHA256，两台机器独立生成也能得到同一套错峰计划；缓存丢失时仍能重建。新日期自然换计划；用户明确改协议版本时可重建当天计划，普通重试不改变时刻。

每轮目标处理2–4条PR，普通批次争取18分钟内完成或交接，复杂内容最多60分钟。唤醒间隔不是每轮时长上限：正在工作就继续当前批次，同一账号串行，跳过已经过去的计划时刻，不补跑、不并行。配对补写后由接收方直接核对并合并，发现问题才退回。待办不足时处理已有并继续其他独立主题，不为数量拆分内容。唤醒是检查和接续工作的机会，不是每轮只能产出一项的节拍。

## 原生任务如何应用

每机仍保留两个Codex原生heartbeat：08:30每日排程、协作执行。不为168个时刻各建任务，不手改内部automation.toml。

Plan返回完整times，不再返回固定组合rrule。使用Next读取已锁定的计划，返回严格晚于当前时间的nextAt和一个小时/分钟的rrule。每次用原生automation_update把已有worker只预约到这一项；日重复规则仅作为单个预约的载体，下一次运行会替换它。

1. 每日08:30：读取最新规范，Doctor，运行Plan/Next，将worker设置为当天第一项未来时刻。
2. 每轮开始：先运行Next，将同一worker推进到下一项未来时刻，再处理GitHub工作，避免中途故障丢失整个后续链条。
3. 收尾：用最新时间再运行Next；若上次预约已过去，推进到新的未来时刻。当天结束自动选明天第一项。不补跑漏过的唤醒。

本地`.local/automation.json`保存actor、workerId、plannerId、planDate、protocolVersion、nextAt、timezone。保留原聊天、模型、通知设置及人类暂停状态；只更新既有任务。原生view若只显示卡片，可只读配置核对字段，更新仍通过工具。

命令：

```powershell
pwsh -NoProfile -File .agents/skills/github-collab/scripts/Invoke-Collab.ps1 -Action Plan -Actor lw-liuwang
pwsh -NoProfile -File .agents/skills/github-collab/scripts/Invoke-Collab.ps1 -Action Next -Actor lw-liuwang
```

B将Actor换成ZicongHe2002，并只管理B自己的机器。

排程提示词：读取最新github-collab，Doctor，Plan锁定当天随机时刻，Next取得未来单个预约。使用原生工具更新已有worker，保存实际结果；不使用Plan的旧minute/minutes/rrule字段，不恢复旧固定分钟组合，不重新抽签，不创建重复任务，不恢复人类暂停。

执行提示词：先读取最新规范并用Next推进原生预约；再连续处理Inbox中的反馈、答案验证、PR和新研究，每轮目标2–4条PR。普通PR验收通过当轮合并；配对PR由接收方实际补写、核对最终diff后直接标ready并merge，发现问题才退回。等待一条交接时继续其他独立主题。普通PR投对方工作仓库，有共同创作才正确署名；已解锁YOLO不重做。普通批次争取18分钟内完成或交接、复杂内容最多60分钟，不因5分钟唤醒强行中断，不并行和补跑；收尾查新交接并核对下一预约仍在未来。日常操作自动执行，无每日硬上限。每天更新同一条摘要，只对重要进展、故障或人类动作通知。

A只能更新A本机；B根据共享交接更新B本机。电脑开机、Codex桌面版运行时触发。前十四天总结银级进度并继续金级，全部目标确认后各自暂停任务。
