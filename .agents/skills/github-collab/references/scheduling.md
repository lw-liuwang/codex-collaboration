# 每20分钟唤醒，双方错开10分钟

2026-11-17用户明确要求“每20分钟吧”，替代初版每天十个随机窗口。每台Windows机器保留两项Codex原生heartbeat：08:30每日排程、白天协作执行。电脑开机、Codex桌面版运行时触发。

## 实际时刻

北京时间09:00–23:00之间，每20分钟唤醒一次，每账号每天42个计划时刻。Plan为每个日期生成同一个小幅随机偏移：A在每小时02–08分、22–28分、42–48分，B在A之后10分钟。双方独立运行同一版本Plan会得到匹配时刻。

例如A在09:05、09:25、09:45，B就在09:15、09:35、09:55。这个例子不是固定日程，具体以Plan输出为准。最后一轮从22时开始，23时不再新启动；复杂轮次可按原来的60分钟上限收尾。

普通轮次争取在15–18分钟内完成并交接，优先验证答案、处理PR反馈和合并，让对方下一轮能继续。复杂研究任务可以持续最多60分钟；同一账号不并行运行，期间新的唤醒跳过或续当前工作，不排队补跑，不把长任务拆成无意义的提交。

## 每日排程

每天08:30运行Plan，读取当天全部times与rrule。通过原生automation_update更新已有worker，保留name、prompt、目标聊天和通知设置。人类已暂停的任务不自动恢复。每轮开始也核对当日计划，日期或协议版本变化时更新本机任务，不等次日才应用新的规范。

本地`.local/automation.json`至少保存actor、workerId、plannerId、planDate、protocolVersion、timezone。先创建worker，再创建planner，保存真实返回ID；后续按ID更新，不重复创建。view若只显示卡片，可以只读对应automation.toml核对字段，更新仍经原生工具，不手改内部文件。

排程提示词：

> 在规范仓库读取最新github-collab和config。Doctor核对身份，运行Plan，使用原生工具更新本机已有worker到当天每20分钟、与对方错开10分钟的计划。保存实际ID、日期和协议版本；不创建重复任务，不改模型，不恢复人类暂停，不补跑错过时刻。

## 每轮做什么

1. 读取最新规范和Inbox，先处理对方需要自己验证、修改或合并的对象。
2. 继续已有研究任务，再主动研究新主题；没有待我处理的交接不代表没有工作。
3. 普通轮次争取18分钟内交接，复杂轮次最多60分钟，不重叠。等待对方时交接并继续可独立完成的内容。
4. 每日同一条摘要更新成果与证据，只有重要进展、故障或人类动作才通知。

执行提示词：

> 从规范仓库使用github-collab，确认本机身份并读取最新Inbox。优先反馈、答案验证与PR检查合并，再继续研究和新贡献；普通PR投对方工作仓库。每20分钟唤醒，普通轮次争取18分钟内交接，复杂内容最多60分钟，期间不另起并行轮次、不补跑。按正确身份与署名实际操作，成功后回读。已获YOLO的账号不再重复尝试；未解锁方按现有交接执行。日常操作自动完成，无每日硬上限；没有交接时主动研究和提交有效内容。

使用现有聊天的heartbeat，不创建新聊天。A只能更新A机器；B通过共享交接自行更新B机器，回填实际启用时刻。无需统一ready。前十四天总结银级进度，继续向金级积累；全部目标确认后各自暂停本机两项任务。
