# 每天十个随机时段

每台 Windows 机器各配置两项 Codex 原生 heartbeat：每日排程、协作执行。电脑需开机、Codex 桌面版保持运行。A 不能替 B 管理另一台机器的本地任务。

## 每日排程任务

北京时间每天08:30执行。脚本 Plan 根据日期、账号、协议版本生成可复现的随机计划：在09–22时中选十个不同小时，每天选一个05–50分的共同分钟。每账号独立，次日重新生成。这不是每次触发各选不同分钟。

通过原生 automation_update 更新已有协作执行任务，保留聊天、提示词和通知设置。实际任务ID保存 `.local/automation.json`。不手改 automation.toml，不用系统计划任务替代原生任务。初始化在当天较晚时，只执行未来时间点；漏跑不补成密集请求。

提示词：

> 在本机规范仓库使用 github-collab，核实当前 GitHub 身份，运行 Plan 生成北京时间当天十个随机时段。通过 Codex 原生工具更新本机已有协作执行 heartbeat，保存实际任务ID。不修改每天十次、每轮一小时和成就目标。失败如实记录，不另外创建重复任务。

## 协作执行任务

每轮最多60分钟，不要求工作满一小时；没有任务可提前结束。上一轮仍在运行时跳过或续做，不重叠。快到时间时完成当前动作、保存和交接，下一轮继续。不要长时间等待对方或轮询无变化的状态。

提示词：

> 在本机规范仓库使用 github-collab。Doctor 核实账号，Inbox 查看共享仓库中我需要处理的交接和等待对方的事项。优先反馈、验证、已有PR/Q&A，再主动研究并提交主题内容。按成就条件安排跨仓库PR、真实共同署名、实际Q&A和YOLO单独尝试。日常GitHub操作自动执行，不逐条询问。每账号每日争取十五个已合并有效PR，不设硬数量上限。review请求必须结合交接mode，YOLO时不要抢先review。每轮最多60分钟，保存结果和下一行动人；没有待办时可研究新内容。只在重要进展、故障或需要人类动作时通知。

使用现有聊天的 heartbeat，不创建新聊天。模型沿用本机默认配置。不在提示词规定无限工作，也不把错过的时段集中补跑。确认原生任务显示的时刻为北京时间，不自动修改系统时区。

## 首次与结束

接入完成即可配置并启动本机任务，不等另一方 ready。缺少另一方仓库或权限时，先研究准备并把所需动作写入交接 Issue。只有实际需要对方账号的动作才等待。

从两边开始实际协作的日期计算十四天阶段；到期总结而不硬停止，继续向金级积累。双方金级全部确认后，分别暂停本机两项原生任务并记录。
