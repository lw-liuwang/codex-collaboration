# 笔记范围与验收

CS336 以 A 本机 Coral 的精选基础笔记作初始参考。GitHub 是后续协作主线，Coral 原稿保留、不自动回写。RSI 以递归自我改进的研究笔记为范围，由 B 的 Codex 自行建立公开资料清单和首批任务。

两边都以原理、因果关系、公式、图解、手算和有参考答案的小练习为主，不要求代码练习，不实施能够自行修改规则或权限的 RSI 系统。辅助计算可验证数字，但不能把模型推测写成已完成实验。

## 一项有效内容任务

任务说明一个明确知识问题、依据的公开来源、缺失或错误之处，以及完成后读者应能判断什么。一个 PR 包含解决同一问题所需的解释、算例、图和验证，不把同一改动的标题、标点、图例、公式各拆一个 PR。没有具体修改理由时不为数量重写正确段落。

建议顺序：为什么需要这个机制 → 输入和已有条件 → 具体操作与依赖 → 同一个算例的中间结果与输出 → 收益和边界。引入术语前先解释对象和作用。图的布局、方向与连线要表达信息，不把一段话搬进方框。

验收核对：公式维度和符号一致；手算从输入走到输出；区分假设示例、理论结论和实际测量；引用能定位原文；适用条件和失败边界没有丢失。小练习与参考答案放在一起，检验核心关系。

## 来源与发布

公开笔记优先引用课程原始材料、论文和项目原文，社区笔记标为社区材料，不冒充课程官方说法。记录 URL、版本/commit 和相关章节。不要整篇转载第三方教材、PDF 或无许可资源；写自己的解释并保留必要引用。没有授权决定前不替用户添加开源许可证。

本机 Coral URI 只作来源登记，不能是对方唯一可用的阅读入口。已发布笔记必须在 GitHub 自包含；去掉本机绝对路径，修正相对链接。Coral HTML 在 GitHub 仅显示源码，静态图转为 SVG/Markdown 表格并提供文字解释；不要声称 GitHub 会执行交互代码。

CS336 初始导入文档标记待技术复核，保留来源版本。导出/转换成功不等于技术验收或视觉验收。RSI 资料由 B 搜集时，优先说明自我改进的对象、反馈信号、评价集、比较基线、证据和失败模式；区分同一基准分数提高与对未见任务的实际改善。
