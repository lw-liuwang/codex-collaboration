## 四项工作

1. **处理自己仓库的全部开放PR。** 完整分页获取列表，逐一检查是否已处理、是否有新head。对方的普通PR由接收方review并实际补写内容，例如推导、反例、例题或修正；将双方真实成果整理进同一个正确共同署名的提交，核对完整最终diff后当轮合并。使用merge commit保留署名，合并绑定最终head并回读结果。存在具体错误或冲突就修复或明确交回，不直接合并错误内容。已完成的PR不重复操作；本人的PR不能给自己提交approve，按实际作者安排协作。旧YOLO无review路径已由2026-11-19强制审批要求替代，不关闭规则或添加绕过名单。
2. **回答对方仓库全部待回答Discussions。** 完整分页读取讨论与评论，不只依赖共享交接Issue。逐个回答自己尚未回答、仍有待解决问题的讨论；已有自己的回答而对方未验证时不重复贴同一个答案，有新追问则继续回复。能形成采纳路径的问题使用isAnswerable=true的Q&A分类。公告、闲聊等不能采纳答案的讨论需要说明分类，不能当作Galaxy Brain成果；不要为了“全部”在没有问题的帖子灌水。自己发起的讨论不冒充回答他人的问题。
3. **核验并采纳自己仓库全部待采纳答案。** 对自己的Q&A逐条读取对方答案，正确则立即mark answer，回读answer.id和回答者。无答案、错误、尚不能核验或非Q&A的对象标清原因与下一行动人；不要空采纳、把提问本身当答案或用自答自采纳代替双账号路径。已有正确采纳结果不撤销重采纳；有新问题另行处理。
4. **至少向对方工作仓库新发布3个PR。** A投rsi-notes，B投cs336-notes；这里统计本轮实际新创建的PR，不用旧PR评论、review、修改标题或合并来充数。不设置7个上限。每个PR包含一个可独立核对的改动与初稿，为对方实际补写留下明确内容任务；涉及未完成共同写作时可Draft，普通完整改动直接Ready。对方仍应按第1项实际协作并整理共同署名。发布不等于合并，也不等于成就到账。

第1–3项没有数量上限，按当前可处理对象清单逐个收敛；第4项是新发PR下限。每轮开始全量发现，收尾再扫新到结果；收尾新到且可立即处理的继续完成。没有对象的项目记录“0个待办”，不需要凭空新提问来补旧的问答配额。等待对方的对象继续交接，不能当作已完成。当前批次持续串行工作，新唤醒不得另起并发批次。

## 怎样判定完成

每轮记录四类证据：自己仓库PR总数/已协作合并/具体阻塞；对方讨论总数/新答复链接/待确认原因；自己讨论总数/新采纳节点/待回答或待修正原因；本轮新PR至少3个的URL和head。正确性只做必要核对，不要求长文或另设人工审批。

如果第1–3项有尚可立即执行但没做的对象，或第4项不足3个，就记录“未完成”并继续，不用“无变化”或已运行工具冒充验收。网络、权限、需要对方修改等阻塞记录准确原因及下一行动人。预算或上下文迫使接续时保存逐项游标与未完成对象，下一轮优先继续，不另造完成状态。

共享handoff Issues仍是双方交接渠道，Assignee表示下一行动人；工作仓库的PR与Discussion是实际待办来源。失败写入先回查对象，防止重复发布或采纳。

## 与成就条件的关系

| 目标 | 对应动作 | 真正计数的结果 |
| --- | --- | --- |
| Pull Shark | 第4项发PR，对方按第1项合并 | 被合并PR的作者；仅发布不计，点merge不等于给合并者计数 |
| Pair Extraordinaire | 第1项双方实际写内容并共同署名后合并 | 被合并PR中包含双方贡献的共同署名提交；review或PR正文致谢不能替代 |
| Galaxy Brain | 第2项回答、第3项对方核验采纳 | 被采纳答案的回答者；A采纳B的答案计B，B采纳A的答案计A |
| YOLO | 历史目标保留记录 | A已确认解锁，不重复；本次强制审批优先，不为未review尝试关闭或绕过规则 |
